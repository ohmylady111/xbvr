# XBVR 中文版：群晖 NAS Docker Compose 部署

## 镜像与适用范围

- 镜像：`ghcr.io/ohmylady111/xbvr:zh-cn`
- 面向 Linux amd64（Intel/AMD 群晖）与 arm64；不包含 armv7 / 32 位 ARM。
- 简体中文和英文可在网页导航栏切换；默认跟随浏览器语言。
- 镜像自带 ffmpeg / ffprobe，启动时会在持久化目录建立指向系统工具的符号链接。
- 本文仅说明部署；不会自动配置外网、路由器或操作你的 NAS。

## 1. 准备目录

在 File Station 建立 `/volume1/docker/xbvr-zh/config`。把同目录提供的 `compose.yaml` 放到 `/volume1/docker/xbvr-zh/`。

修改 Compose 的视频路径：

```yaml
- /volume1/video/VR:/videos:ro
```

冒号左边必须是 NAS 上真实存在的 VR 视频目录，右边 `/videos` 不用改。默认 `ro` 只读，XBVR 无法移动、重命名或删除原片；如果你日后确实需要这些功能，再自行改成 `rw`。不要为了省事挂载整个 `/volume1`。

持久化目录：

```yaml
- /volume1/docker/xbvr-zh/config:/config
```

数据库、配置、缓存、封面与搜索索引都写入这里；目录需要可写，缓存可能占较大空间。不要填写 PUID/PGID：该镜像未实现这类环境变量，默认以 root 运行；媒体只读用于保护原片。不需要 privileged，也不需要挂载 Docker socket。

## 2. Container Manager 图形部署

1. 安装并打开群晖 **Container Manager**。
2. 进入 **项目 → 新增**，名称填写 `xbvr-zh`。
3. 项目路径填写 `/volume1/docker/xbvr-zh`。
4. 选择现有 `compose.yaml`（或上传它 / 把内容粘贴到编辑器）。
5. 检查两条挂载路径真实存在，创建并启动项目。
6. 查看日志，等首次数据库迁移、索引初始化完成。

旧版 DSM 只有 Docker 套件、没有“项目”功能时，可使用 SSH Compose，或按相同参数手工创建容器。

### SSH 方式（可选）

```sh
cd /volume1/docker/xbvr-zh
sudo /usr/local/bin/docker compose -f compose.yaml config
sudo /usr/local/bin/docker compose -f compose.yaml pull
sudo /usr/local/bin/docker compose -f compose.yaml up -d
sudo /usr/local/bin/docker compose -f compose.yaml logs --tail=100 -f
```

如果不支持 `docker compose`，用已安装的 `docker-compose` 替代；不要另装第二套 Docker 服务。

## 3. 打开网页与初始化

浏览器访问 `http://NAS局域网IP:9999/ui/`。你的 NAS 可用：

**http://192.168.50.202:9999/ui/**

1. 导航栏选择 **简体中文**（窄屏先打开菜单）。
2. **设置 → 刮削器**，只启用需要的站点，运行刮削器拉取元数据。
3. **设置 → 存储**，添加容器内路径 **`/videos`**，不要填写 NAS 的 `/volume1/...`。
4. 扫描后在文件页检查匹配情况。

刮削器访问外部站点受网络、站点状态和上游兼容性影响；中文 UI 不会自动翻译影片标题和简介，也不保证所有站点可用。

## 4. 网络和 VR 播放器

默认 Compose 使用 `network_mode: host`，方便 DLNA 多播发现，与上游建议一致。

- **不要同时填写 `ports:`**。
- 网页使用 TCP 9999，WebSocket 默认 TCP 9998，DLNA HTTP 默认 TCP 1338，并使用 SSDP UDP 1900 多播。
- 同一 NAS 上端口冲突时先停下检查；不要直接覆盖其他容器。群晖 Media Server 也可能使用 SSDP，自动发现异常时需要检查冲突和网络隔离。
- NAS 和头显应在同一局域网；访客 Wi-Fi、AP 隔离和跨 VLAN 会影响发现。
- 如启用了 DSM 防火墙，仅允许可信局域网访问相关服务，不要在路由器转发到公网。默认上游不强制网页登录，部署后检查 **高级设置** 中认证选项。
- HereSphere / DeoVR 可按 **设置 → 播放器** 中显示的实际 URL 连接。

不需要 DLNA 时，可以删除 `network_mode: host`，改为：

```yaml
    ports:
      - "9999:9999"
      - "9998:9998"
```

这样网页与直接 API 可用，但不要期待 DLNA 自动发现；网页端口冲突可将左侧改为 `19999:9999`，访问端口相应改为 19999。

## 5. 更新、备份与回滚

**更新前先停止容器并备份整个 config 目录。** 上游启动可能执行数据库迁移，仅换回旧镜像不一定能回滚数据库。

在 Container Manager 停止项目，复制 `config` 到独立备份目录，然后更新镜像并重新创建/启动项目。SSH 对应：

```sh
cd /volume1/docker/xbvr-zh
sudo /usr/local/bin/docker compose stop
# 此时用 File Station 或备份工具复制整个 config 目录
sudo /usr/local/bin/docker compose pull
sudo /usr/local/bin/docker compose up -d
```

重建容器不影响上述绑定挂载中的配置；不要删掉 config。需要回滚时停止容器、恢复完整备份，并使用匹配旧版本的镜像标签或摘要。生产中可把 `:zh-cn` 替换成发布验证后的 `@sha256:...` 摘要以锁定版本。

### 从官方容器迁移

先停旧容器、备份原数据库和配置，不要两个进程共用一个数据库。官方常见挂载是 `/root/.config/`，实际数据在其子目录 `xbvr/`。本镜像 `/config` 对应的是**应用数据目录本身**，因此复制旧的 `xbvr/` 内容到新 `config/`，不要多套一层 `config/xbvr/`。旧容器内媒体路径尽量继续使用相同值，避免已有文件记录失效。不要拿唯一的生产副本直接试迁移。

## 6. 常见问题

- `pull access denied` / `unauthorized`：检查镜像地址和 GHCR 包是否公开；不要把 GitHub token 写进 Compose。网络超时与权限错误是两回事。
- `no matching manifest`：NAS 架构不是 amd64/arm64，或拉取的标签不对。
- 打开还是英文：导航栏选中文并刷新，确认没有拉错成官方镜像。自定义保存搜索名称、影片数据和后端日志不在汉化范围内。
- 找不到视频：确认宿主目录存在、挂载正确，网页添加的是 `/videos`，DSM 文件权限允许读取。
- 无法保存 / SQLite 错误：检查 config 可写、磁盘空间，确认没有两个容器同时操作同一目录。
- 网页打不开：看项目状态和日志，检查 9999 冲突、防火墙以及是否仍在初始化。
- 退出后原片还在：正常；只读挂载就是为了保护原片。
